A "V" built from the two halves of the product: a profile speaking on the
left, a receipt carrying a rupee on the right. Vaani and track, in one letter.

---

## 1. What changed, and why twice

The mark has had three forms. Recording them because the second one is still
referenced in older docs.

| | Mark | Why it went |
|---|---|---|
| 1 | Four vertical bars, a waveform, hand-built inline in the capture screen | Borrowed from the Wispr Flow reference. Bars-in-a-row is what every voice app reaches for, and it said nothing about money |
| 2 | A monoline `₹` whose crossbars were drawn as sound waves, as SVG paths in code | Replaced by supplied artwork, not by a fault of its own |
| 3 | **Current.** The "V" lockup | Supplied by the product owner |

Form 2 was drawn in code, which is why the icons were `ImageResponse` routes:
the mark *was* a set of path strings, so every size could be rendered from the
same source with no raster to drift. Form 3 is a raster illustration with
gradients and soft shading. None of that survives being redrawn as paths, so
the icon pipeline changed shape with it.

## 2. What was done to the supplied file

The source is a 1254×1254 lockup: the mark, the word "VaaniTrack" beneath it,
and a "SPEAK · TRACK · LIVE SMARTER" tagline beneath that. Three changes, all
in `scripts/build-logo.mjs`, all reproducible:

**The wordmark and tagline were cropped away.** Every place the mark appears,
the app already sets "VaaniTrack" in type beside it. Baking the name into the
image says it twice and stops it scaling with the type around it. The crop
bounds came from a row-by-row scan of the three content bands, not by eye:
the mark is `y 292–780`, `x 312–942`.

**The background was made transparent**, so the mark sits on paper, on mint,
and on the dark chamber without a visible box. This is a flood fill inward
from the edges, deliberately not a global colour match: the receipt inside
the mark is very nearly the same cream as the background, and matching
globally would punch holes straight through it. Edge pixels are feathered,
because a cream fringe is invisible on paper and obvious on the mint icon
field.

**The gold became green.** The supplied art used gold for the sound waves and
the rupee. The app has exactly one warm accent, Ember Glow, and `DESIGN.md`
reserves it for a single meaning: *the microphone is live.* A gold mark would
either collide with that or quietly introduce a second warm accent, so the
hue was rotated to `158°`, between Forest Ink and Mint Deep.

The rotation keeps each pixel's own lightness and changes only hue, so the
original shading survives rather than flattening into one flat green.
Saturation is scaled to 0.78 because gold is far more saturated than anything
else in this palette and a green at the same level reads acidic.

Gold and the receipt's parchment cream are separated by red-minus-blue, not by
a hand-drawn mask: gold (~`176,128,64`) has red far above blue, parchment
(~`240,224,192`) does not. That threshold recolours the waves and the rupee
and leaves the receipt alone.

## 3. How it is used

`Logo.tsx` renders `public/logo.png` through `next/image`. The artwork is
**wider than it is tall** (661×512, aspect 1.291), so `size` is its *height*
and width follows. A row of elements at the same `size` then lines up on
their heights, the way type does.

> Corrected 20 September 2026. This section previously said 631×489, the
> trimmed source's dimensions *before* `build-logo.mjs`'s final resize; the
> committed `public/logo.png` is 661×512. `Logo.tsx`'s `ASPECT` constant now
> matches the shipped file rather than an intermediate one.

> If the source art is ever replaced, `scripts/build-logo.mjs` prints the new
> aspect ratio and will tell you to update `ASPECT` in `Logo.tsx`.

Icons are static PNGs, generated by the same script and committed:

| File | Size | Field |
|---|---|---|
| `src/app/icon.png` | 64 | mint, 10% padding |
| `src/app/apple-icon.png` | 180 | mint, 14% |
| `public/icon-192.png` | 192 | mint, 14% |
| `public/icon-512.png` | 512 | mint, 14% |
| `public/icon-512-maskable.png` | 512 | mint, **22%**, Android's safe zone |

Icons are full-bleed with no self-drawn border, since iOS and Android apply
their own rounding and a border would be clipped unevenly at exactly the edge
it is meant to define.

`src/lib/logoIcon.tsx` and the five `ImageResponse` icon routes were deleted;
static files replace them, and Next picks up `icon.png` and `apple-icon.png`
by file convention.

## 4. The known cost

**Detail is lost below about 32px.** Checked at 16, 24, 32 and 40px: the
profile and the sound waves dissolve, and what survives is a green "V". That
still reads as a distinct mark rather than mush, and the favicon is legible,
but it is a real trade against form 2, which was designed to stay sharp at
16px because it was a single monoline glyph.

If the favicon ever needs to carry more at small sizes, the fix is a
simplified small-size variant rather than a different logo. Nothing here
prevents that.

> **Acted on, 20 September 2026.** This section is why the readability pass
> (`docs/design/README.md` item 6, forthcoming) set a 32px floor: no `<Logo`
> call site in `src/` renders it smaller. The favicon and the icon files are
> exempt by necessity — they are fixed by OS and manifest convention, not by
> this component — and were already checked against this same finding.
